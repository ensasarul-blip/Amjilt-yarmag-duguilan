
4. Терминалаа **хааж, дахин нээгээд** `node -v` гэж шалгана

## Алхам 4 — Өгөгдлийн санг үүсгэх (SQL 4 файл)

Энэ бол **хамгийн чухал алхам**. Дараалал нь чухал — 1 → 2 → 3 → 4.

Supabase-ийн зүүн талын цэснээс **SQL Editor** (🖥 дүрстэй) сонгоно.

Дараах 4 файлыг **тус бүрд нь** дараах байдлаар ажиллуулна:

1. **New query** товчийг дарна
2. Төслийн `supabase/` хавтас доторх файлыг текст засварлагчаар нээнэ
3. Дотор байгаа бүх текстийг хуулж (Cmd+A → Cmd+C), SQL Editor руу буулгана
4. **Run** товчийг дарна (эсвэл Cmd+Enter)
5. `Success. No rows returned` гэх мэт ногоон хариу гарвал БОЛСОН

| Дараалал | Файл | Юу хийдэг вэ |
|---|---|---|
| 1 | `supabase/01_schema.sql` | Хүснэгтүүдийг үүсгэнэ |
| 2 | `supabase/02_functions.sql` | Суудал хуваарилах логикийг үүсгэнэ |
| 3 | `supabase/03_policies.sql` | Аюулгүй байдал, Realtime-г тохируулна |
| 4 | `supabase/04_seed.sql` | 50 дугуйлан, 27 бүлгийг оруулна |

### Зөв болсныг шалгах

4-р файл ажиллахад доод талд хүснэгт гарч ирнэ:

```
niit_duguilan | hyazgaartai
      50      |      8
```

**50** дугуйлан, **8** нь хязгаартай (Төгөлдөр хуур 2, Усан сэлэлт 6) байвал зөв.

> ⚠️ `04_seed.sql`-ийг **зөвхөн НЭГ УДАА** ажиллуулна. Хоёр удаа ажиллуулбал
> дугуйлангууд давхардана. Давхардвал SQL Editor дээр `delete from public.clubs;`
> гэж ажиллуулаад 4-р файлыг дахин ажиллуулна.

## Алхам 5 — Realtime асаах (суудал ШУУД шинэчлэгдэх)

⚠️ **Энэ алхмыг заавал ГАРААР хийнэ.** SQL-ээр хийх боломжгүй — Supabase энэ
тохиргоог зөвхөн самбараас өөрчлүүлдэг.

1. Зүүн цэснээс **Database** → **Replication**
   *(эсвэл шинэ загварт: **Database** → **Publications**)*
2. `supabase_realtime` гэсэн нийтлэлийг олж, **source / tables** тоог дарна
3. Хүснэгтүүдийн жагсаалтаас **`club_seat_counts`** мөрийг олно
4. Түүний унтраалгыг **асаана** (`Insert`, `Update` хоёр хангалттай)
5. **Save / Enable** дарна

### Яагаад хэрэгтэй вэ

| | Realtime АСААЛТТАЙ | Realtime УНТРААЛТТАЙ |
|---|---|---|
| Өөр хүн бүртгүүлэхэд | Суудал **тэр даруй** буурна | **20 секундын дараа** буурна |
| Вэбсайт ажиллах уу | ✅ | ✅ |

Өөрөөр хэлбэл **энэ алхмыг алгасвал ч вэбсайт бүрэн ажиллана** — зөвхөн суудлын
тоо шууд биш, 20 секунд тутам шинэчлэгдэнэ.

> 💡 Хэрэв `club_seat_counts` жагсаалтад харагдахгүй бол `01_schema.sql` файлыг
> ажиллуулаагүй байна гэсэн үг. Алхам 4-рүү буцна уу.

## Алхам 7 — Түлхүүрүүдийг хуулж `.env.local` файл үүсгэх

1. Supabase дээр: **Project Settings** (⚙) → **API Keys** (эсвэл **Data API**)
2. Хоёр зүйлийг хуулна:
   - **Project URL** — `https://xxxxxxxx.supabase.co` хэлбэртэй
   - **Publishable key** — `sb_publishable_...` гэж эхэлсэн мөр

   > 💡 Хуучин төслүүд дээр энэ нь **anon / public** гэж нэрлэгдээд
   > `eyJhbGciOi...` гэж эхэлсэн урт мөр байж болно. Аль нь ч болно.

Одоо терминал дээр (төслийн хавтас дотроо байгаа эсэхээ шалгаарай):

```bash
cp .env.local.example .env.local
```

`.env.local` файлыг текст засварлагчаар нээгээд хоёр мөрийг бөглөнө:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_...
```

> ⚠️ `=` тэмдгийн хоёр талд **зай байх ёсгүй**. Хашилт ч бас хэрэггүй.
>
> ⚠️ **ХАМГИЙН ЧУХАЛ ЗҮЙЛ.** Supabase хоёр төрлийн түлхүүр өгдөг:
>
> | Түлхүүр | Нууц уу? | Энд хэрэглэх үү? |
> |---|---|---|
> | `sb_publishable_...` (эсвэл `anon`) | ✅ Нууц БИШ | ✅ Тийм |
> | `sb_secret_...` (эсвэл `service_role`) | 🔴 **ТУН НУУЦ** | ❌ **ХЭЗЭЭ Ч ҮГҮЙ** |
>
> Publishable түлхүүр нь хөтөч дээр ил харагддаг бөгөөд энэ нь хэвийн зүйл.
> Аюулгүй байдлыг өгөгдлийн сангийн дүрмүүд (RLS) хангадаг.
>
> **Secret түлхүүр** нь бүх дүрмийг тойрч сурагчдын нэр, утсыг бүгдийг нь
> уншиж, устгаж чадна. Түүнийг энэ төсөлд ОГТ хэрэглэхгүй. Хэрэв санамсаргүйгээр
> хэн нэгэнд (чат, и-мэйл, скриншот) илгээсэн бол Supabase дээр
> **Project Settings → API Keys → Rotate** дарж шууд солиорой.

## ❓ Асуудал гарвал

**"Тохиргоо дутуу байна" гэж гарч байна**
→ `.env.local` файл байхгүй эсвэл дутуу. Алхам 7-г дахин хийнэ.
→ Файлыг хадгалсны дараа `npm run dev`-ээ зогсоогоод (Ctrl+C) дахин асаана.

**"Өгөгдлийн сантай холбогдож чадсангүй"**
→ Алхам 4 дэх 4 SQL файлыг бүгдийг нь дараалалд нь ажиллуулсан эсэхээ шалгана.

**Дугуйлангууд харагдахгүй байна**
→ `04_seed.sql` ажиллуулаагүй байна. Supabase → Table Editor → `clubs` хүснэгтэд
50 мөр байгаа эсэхийг хараарай.

**Дугуйлан 2 дахин харагдаж байна**
→ `04_seed.sql`-ийг хоёр удаа ажиллуулсан байна. SQL Editor дээр
`delete from public.clubs;` → Run, дараа нь `04_seed.sql`-ийг **нэг удаа** ажиллуулна.

**Админаар нэвтэрч чадахгүй байна**
→ Алхам 6 дээр "Auto Confirm User" асаасан эсэхээ шалгана. Эс бөгөөс
хэрэглэгчийг устгаад дахин үүсгэнэ.

**Суудлын тоо шууд шинэчлэгдэхгүй байна**
→ Алхам 5 (Realtime) хийгээгүй байна. Хийгээгүй ч 20 секунд тутам шинэчлэгдэнэ.

**Хөтчийн console дээр улаанаар `WebSocket ... _next/hmr ... failed` гэж олон гарч байна**
→ Энэ нь **алдаа биш**. Next.js-ийн хөгжүүлэлтийн горимын "кодыг автоматаар шинэчлэх"
суваг бөгөөд вэбсайтын ажиллагаанд огт нөлөөлөхгүй. **Vercel дээр огт гарахгүй.**
→ Хэрэв та `localhost` биш, сүлжээний хаягаар (жишээ нь `192.168.5.152:3000` —
утаснаасаа үзэх гэж) орж байгаа бол `next.config.ts` доторх `allowedDevOrigins`
жагсаалтад тухайн хаягаа нэмнэ. 192.168.x.x, 10.x.x.x хаягууд аль хэдийн нэмэгдсэн байгаа.
→ Нэмсний дараа хуудсаа **Cmd+Shift+R** дарж шинэчилнэ.

**Vercel дээр ажиллахгүй байна**
→ Vercel → Settings → Environment Variables дээр хоёр мөр байгаа эсэхийг
шалгаад, **Deployments → Redeploy** дарна.

## 🔒 Суудлын хязгаар яагаад найдвартай вэ

Хамгийн түгээмэл алдаа: 15 суудалтай дугуйланд 16 хүн бүртгэгдэх.
Энэ нь хоёр хүн **яг нэг мөчид** товч дарахад тохиолддог — хоёул "14 хүн байна,
суудал байна" гэж уншаад хоёул бүртгэгддэг.

Энэ вэбсайт үүнийг **өгөгдлийн сангийн түвшинд** шийдсэн:

```
1. Дугуйлангийн мөрийг ТҮГЖИНЭ      (SELECT ... FOR UPDATE)
2. Түгжээний доор бодит тоог тоолно
3. Суудал байвал бүртгэнэ, үгүй бол хүлээлгийн жагсаалтад
4. Түгжээг тавьж өгнө
```

Хоёр дахь хүн 1-р алхам дээр **хүлээнэ**. Эхний хүн дуусахад л үргэлжилнэ —
тэр үед тоо аль хэдийн 15 болсон байх тул хүлээлгийн жагсаалтад орно.

Энэ нь `supabase/02_functions.sql` файл дотор `register_student` функц дээр хийгдсэн.
`npm test` командаар 20 болон 40 зэрэгцээ хүсэлтээр шалгадаг.

Мөн: **зөвхөн** frontend дээр шалгадаггүй. Хэн нэгэн вэбсайтыг тойрч шууд
өгөгдлийн сан руу хүсэлт илгээсэн ч хязгаараас хэтрэхгүй.
